# CLAUDE.md

Рабочий язык — русский. Это не кодовая база, а проект развития теории ФТС
(«лестница различимости»). Продукт — статья, карточки и решения в `work/`
(главное: `work/v14_rebuild/`). Python-скрипты — только инструменты проверки.
Принцип: диск — источник истины, контекст — расходник. Писать на диск сразу.

## Старт сессии
Прочитать: `AGENTS.md` (подаётся автоматически) → `work/STATE.md` → `work/notation.md`.
Дальше по задаче: `PROJECT_INSTRUCTIONS.md`, `work/DOCUMENT_MAP.md`.

## Окружение
- `py -3.11 -X utf8 ...` (нужен sympy; системный 3.13 его не имеет). Всегда `-X utf8`.
- `core.autocrlf` не включать; не снимать `-text` с `source/` (SHA256 требует байтовой идентичности).
  Каталоги `source/` внутри статей arXiv — неизменяемые первоисточники.

## Команды (из корня)
- `tools/verify.py --strict` — целостность канона: 0 mismatch, 0 extra
- `tools/query.py card|context|find|deps|stats` — точечный доступ к канону (целиком в контекст не грузить)
- `tools/check_project_consistency.py` — пять обязательных проверок
- `work/v14_rebuild/verification.py` (C01–C62; `--only C06` — частичная диагностика)
- `work/v14_rebuild/verification_c63|c77|c85|c93|c96.py`, `verification_windows_table.py` —
  не входят в общий маршрут, запускать вручную по одному
- `tools/rebuild_canon.py` — после правок `source/`

FAIL ≠ контрпример: сначала диагностика причины (`PROJECT_INSTRUCTIONS.md#status`).
Частичный прогон не заменяет полный перед завершением формальных правок.

## Инварианты
1. `source/` редактируем без отдельного разрешения; после правок — MANIFEST,
   производные и `verify.py --strict`.
2. No-smuggling: у понятий ФТС нет априорного смысла. Выводы помечать
   `[карточка ID]` / `[триплет s→p→o]` / `[лист row]` / `[внешнее]`; чего нет —
   писать «нет в артефактах». Канон побеждает внешнее (конфликт → `work/EXTERNAL_CONFLICTS.md`).
3. Не смешивать: `¬A` ≠ `0_A` ≠ `−A`; candidate/overlay ≠ canonical_strict;
   phase ≠ −A; branch access ≠ Lift; array ≠ tensor; М ≠ Ч ≠ оверлей.
   Полный список — `work/notation.md`.
4. Статусы повышаются только через `SP_*` и критерии К1–К5. Авторское принятие,
   доказательство и эмпирика — разные оси; предложения ассистента автору не приписываются.
5. Формат анализа: Найдено → зависимости → вывод → что не закрыто.
