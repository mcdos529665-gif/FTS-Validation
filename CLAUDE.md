# CLAUDE.md

Рабочий язык — русский. Это проект развития теории ФТС («лестница различимости»).
Основной текст: `work/v14_rebuild/FTS_v14_paper.md`; Python обеспечивает доступ
к карточкам и машинные проверки.

## Старт и процедуры

Краткий контракт — [AGENTS.md](AGENTS.md). Перед содержательной работой один раз
прочитать [STATE](work/STATE.md), перед анализом — [notation](work/notation.md).
Простые вопросы, небольшие редакторские изменения и настройка приложения этого
не требуют. Из [PROJECT_INSTRUCTIONS.md](PROJECT_INSTRUCTIONS.md) читать только
раздел по текущей задаче. Размещение результатов: [DOCUMENT_MAP](work/DOCUMENT_MAP.md).

Работать из полного корня проекта, где есть `source/`, `tools/` и `work/`.
Если этих каталогов нет в текущем worktree, сначала установить расположение
полного checkout; отсутствие файлов не означает отсутствие материалов проекта.
Диск хранит результат работы; контекст чата служит для текущего шага.

## Доступ и проверки

Запускать из корня с `-X utf8` и интерпретатором с нужными зависимостями.
На 2026-10-05 Python 3.11.9 содержит SymPy 1.14.0; Python в `C:/Python313`
не содержит SymPy. Пример полного маршрута:

```text
py -3.11 -X utf8 tools/check_project_consistency.py
py -3.11 -X utf8 tools/query.py stats
py -3.11 -X utf8 tools/query.py card U_07
py -3.11 -X utf8 tools/query.py context U_07 1
py -3.11 -X utf8 tools/query.py find фаза
py -3.11 -X utf8 tools/query.py deps OP_Lift
py -3.11 -X utf8 work/v14_rebuild/verification.py --only C06 C29
```

Полный маршрут включает целостность канона, граф, C01–C62, отдельные кандидатные
проверки C63–C99, таблицу окон, аудит и воспроизводимость выгрузки.
Состав и коды выхода: [PROJECT_CONSISTENCY](work/PROJECT_CONSISTENCY.md).
`--only` — частичная диагностика с предпосылками; она не заменяет полный прогон.
C63–C99 проверяют конкретные модели/сетки/тождества из дополнений; PASS не
удостоверяет общую истинность интерпретации ФТС и не повышает `St_FTS`.
`crosscheck.py` даёт доступ к карточкам; трассируемость проверяет `run_audit.py all`.
Для o20 нужны `numpy`, `pandas`, `scipy`, `scikit-learn`; протокол фиксируется
до прогона. Остальные команды: [процедура](PROJECT_INSTRUCTIONS.md#commands).

## Канон и смысл

`source/` — редактируемый активный канон. Релиз, состав и контрольные суммы
читать из `source/MANIFEST.json`, количества — через `tools/query.py stats`.
Не загружать полный дамп, если достаточно конкретных карточек.
Редактирование и обновление производных: [canon](PROJECT_INSTRUCTIONS.md#canon).
Не включать `core.autocrlf` и не снимать `-text` с `source/`, TSV и JSONL.

Содержательные выводы обосновывать карточкой, триплетом, листом либо помечать
`[внешнее]`. При конфликте канон определяет содержание ФТС; расхождение записать
в `work/EXTERNAL_CONFLICTS.md`. Без основания: `нет в артефактах`.
Сохранять точные формулы и группировку; различать регистры и оверлеи,
`¬A`, `0_A`, `⊖A`, арифметический минус и фазовый поворот;
`branch access ≠ Lift`; `array ≠ tensor` без закона преобразования.

FAIL требует диагностики. Проверенный контрпример к точному утверждению ведёт
к его отзыву/сужению; ошибка среды, реализации или области проверки требует
исправления свидетельства. Авторское принятие, математическое доказательство
и `St_FTS` различаются. Повышение — через SP/К1–К5 и запись в графе.
`SP_LIMITS` фиксирует пересматриваемые пробелы оснований; исследование кандидатов
разрешено. Действующая процедура: [status](PROJECT_INSTRUCTIONS.md#status).
