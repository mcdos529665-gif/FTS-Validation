 ## 1. Как это устроено (коротко)
  - **Встроенные команды** — логика зашита в сам Claude Code (`/clear`, `/model`, `/config`…). - **Штатные навыки (bundled skills)** — идут в комплекте с Claude Code, но   реализованы как промпт-инструкции, а не жёсткий код (`/code-review`, `/loop`,
   `/claude-api`…). Вызываются точно так же, как и обычные навыки — набором `/имя`. - **Штатные workflow** — то же самое, но по капоту работают через   оркестрацию нескольких субагентов (`/deep-research`). - **Личные / проектные / плагинные навыки** — добавлены сверх стандартного
   набора: из `~/.claude/skills/` (личные, все проекты), `.claude/skills/`   (только этот проект) или из установленного плагина (`plugin-name:skill-name`).   Плагинные навыки вызываются через двоеточие: `/bio-research:start`,   `/anthropic-skills:docx` и т.д.
 - **MCP-промпты** — некоторые MCP-серверы публикуют свои промпты как команды   вида `/mcp__<server>__<prompt>`; появляются динамически при подключении сервера. - Полный список того, что доступно именно сейчас — команда `/skills` (навыки)
   или ввод `/` и прокрутка меню (все команды). Этот документ — снимок на   дату выше, часть значений (номера версий, наличие фич) может расходиться   с будущей версией Claude Code. - Важный нюанс из официальной документации: часть встроенных команд
   дополнительно выведена в инструмент Skill (тем, чем я, ассистент, тоже могу   их вызвать программно) — подтверждённо это `/init`, `/review`,   `/security-review`. Остальные встроенные команды (`/compact` и т.п.) через   Skill недоступны — их вызывает только пользователь вручную.
  ---  ## 2. Встроенные команды и штатные навыки — официальный реестр  Обозначения: `<arg>` — обязательный аргумент, `[arg]` — необязательный. Пометка **[навык]** = bundled skill, **[workflow]** = bundled workflow;
 остальное — чистая встроенная логика CLI.

  ## 4. Навыки, добавленные сверх стандартного набора (эта машина/сессия)  Ниже — то, что подтверждено списком навыков именно этой сессии, но не входит в штатный реестр §2 (значит, это личные или плагинные навыки, установленные
 у пользователя). Вызов через двоеточие для плагинных.  ### 4.1 `/graphify` (личный навык, `~/.claude/skills/graphify/SKILL.md`)
  Превращает любую папку (код, документы, статьи, изображения, видео) в навигируемый граф знаний: интерактивный HTML, JSON под GraphRAG и
 GRAPH_REPORT.md на человеческом языке. Особенно триггерится, когда в проекте уже есть `graphify-out/` (как в этом репозитории) — тогда вопрос о кодовой базе сначала стоит трактовать как запрос к графу.  Формы вызова (из `## Usage` самого SKILL.md, источник — файл в п.4 списка):
  ``` /graphify                                             # полный пайплайн по текущей директории → Obsidian vault /graphify <path>                                      # полный пайплайн по конкретному пути /graphify https://github.com/<owner>/<repo>           # склонировать репозиторий и построить граф
 /graphify https://github.com/<owner>/<repo> --branch <branch>  # конкретная ветка
 /graphify <url1> <url2> ...                           # несколько репозиториев → один общий граф
 /graphify <path> --mode deep                          # более тщательное извлечение, больше INFERRED-рёбер /graphify <path> --update                             # инкремент: только новые/изменённые файлы /graphify <path> --directed                           # направленный граф (source→target)
 /graphify <path> --whisper-model medium               # модель Whisper покрупнее для транскрипции
 /graphify <path> --cluster-only                       # пересчитать только кластеризацию на готовом графе
 /graphify <path> --no-viz                             # без визуализации, только отчёт + JSON /graphify <path> --svg                                # экспорт graph.svg (Notion, GitHub)
 /graphify <path> --graphml                            # экспорт graph.graphml (Gephi, yEd)
 /graphify <path> --neo4j                              # graphify-out/cypher.txt для Neo4j
 /graphify <path> --neo4j-push bolt://localhost:7687   # прямой пуш в Neo4j
 /graphify <path> --mcp                                # MCP stdio-сервер для доступа агентов
 /graphify <path> --watch                              # автопересборка при изменениях кода /graphify <path> --wiki                               # вики для обхода агентами (index.md + статья на community) /graphify <path> --obsidian --obsidian-dir <путь>     # записать vault в свой путь
 /graphify add <url>                                   # подтянуть URL в ./raw, обновить граф /graphify add <url> --author "Имя"                    # кто написал
 /graphify add <url> --contributor "Имя"               # кто добавил в корпус
 /graphify query "<вопрос>"                             # обход BFS — широкий контекст /graphify query "<вопрос>" --dfs                       # обход DFS — конкретный путь /graphify query "<вопрос>" --budget 1500               # ограничить ответ N токенами
 /graphify path "УзелА" "УзелБ"                         # кратчайший путь между двумя узлами /graphify explain "Термин"                             # объяснение узла человеческим языком /graphify --help                                      # печатает этот же блок и останавливается
 ```  Согласно глобальному `CLAUDE.md` пользователя (`~/.claude/CLAUDE.md`), при вводе `/graphify` ассистент обязан вызывать этот навык раньше любых других действий.  ### 4.2 `anthropic-skills:*` — офисные документы и дизайн (плагин)

 ## 5. Не слэш-команды, но рядом: типы субагентов  Пользователь их не набирает через `/имя` — их выбирает сам ассистент через инструмент Agent/Task, когда делегирует часть работы. Упомянуты здесь только
 для полноты картины и чтобы не путать со скиллами:  - `claude`, `general-purpose` — общего назначения.
 - `claude-code-guide` — вопросы про сам Claude Code / Agent SDK / Claude API.
 - `Explore` — быстрый read-only поиск по коду. - `Plan` — проектирование плана реализации.
 - `statusline-setup` — настройка статус-строки. - `fts-routine` — **проектный**, определён в `.claude/agents/fts-routine.md`
   этого репозитория: механические детерминированные прогоны
   `tools/verify.py`, `tools/query.py`, `tools/oq_pool.py --write`,
   `work/v14_rebuild/verification.py`, `probes.py`, `crosscheck.py`. Явно
   не для оценки содержания ФТС, решений о статусах карточек, правки файлов   или мутирующих команд (`import_from.py`, `git commit/push`, `git init`).
  ---  ## 6. Заметки, специфичные для этого проекта
  - Согласно `~/.claude/CLAUDE.md` (глобальные инструкции пользователя),   `/graphify` — единственный навык с жёстким правилом «вызывать раньше   любых других действий» при явном вводе пользователем. - `/code-review ultra` и его устаревший алиас `/ultrareview` — платные и
   запускаются только пользователем; ассистент не должен пытаться вызвать их   сам ни через Bash, ни иначе. - Если версия Claude Code на машине старше отмеченных в реестре (§2) минимальных   версий — соответствующая команда может быть недоступна («Unknown command»).
