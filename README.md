# ФТС — исследовательский проект лестницы элементарных абстракций

## Задача проекта

Исследовать и обосновать связность элементарных абстракций в заявленной структурной
сложности: установить минимальные выражения уровней, основания их порядка и связи,
необходимость переходов и область применимости лестницы ФТС.

Каждая ступень выражает определённую структурную сложность различения. Соответствие
сложности ступени обосновывается через минимальную форму, необходимую роль,
условия и объявленную модель стоимости. Связность, необходимость каждого перехода
и глобальная единственность лестницы являются отдельными обязательствами.

Постоянная машинная сущность проекта: [PROJECT.json](PROJECT.json), ID `FTS`.
В авторитетном графе ей соответствует `project_fts`. Запись задачи принята по
прямому указанию пользователя 2026-10-03.

## Критерий содержания

Каждое содержательное исследовательское утверждение должно иметь явный адрес:

| Область | Что утверждение проясняет |
|---|---|
| Основания связности | Почему уровни связаны и какие условия обеспечивают связь |
| Лестница в целом | Порядок, минимальность, полноту, общие закономерности и область |
| Конкретный уровень | Его минимальную форму, роль различения, носитель и границы |
| Переход или связь между уровнями | Что сохраняется и появляется; окна, проекции и межуровневые отношения |

Привязка может идти через другие утверждения, если каждое звено имеет источник,
область и понятную роль: определяет, предполагает, обосновывает, уточняет,
ограничивает или опровергает. Гипотезы и аналогии сохраняют соответствующее
обозначение. Для незакрытого обоснования записывается конкретное обязательство.

Внешние источники, методы и проверки связываются с исследуемым утверждением.
Оригиналы источников, исторические версии и производные выгрузки учитываются по
своему назначению. Наличие ребра, общий документ и успешная структурная проверка
сами по себе не устанавливают содержание или истинность связи.

Канон пересматривается по действующей процедуре; оригинальные исходники внешних
статей сохраняются. `¬A`, `0_A`, `−A`, регистры и оверлеи различаются;
`branch access ≠ Lift`, `array ≠ tensor` без закона преобразования.
