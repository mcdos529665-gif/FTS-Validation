узлов (решение / лемма / тест-площадка / формула), каждый из которых закрывает

(пунктов на единицу работы). Это следующий уровень над пулами: пул отвечает
«какие вопросы похожи», точка пересечения — «что одно надо сделать, чтобы
просело много».

  типы работ, ТОП-3. П1 закрыт (probes.py + REFUTED.md).
- graphify-слой (`graphify-out/`, коммит 56fa137) — навигация по канону
  (EXTRACTED доверяй / AMBIGUOUS сверяй с каноном); `tools/query.py deps` —
  транзитивные depends_on.

Чего слой пулов НЕ делает (и что и есть искомые «точки пересечения»):
1. **Хабы не ранжируются**: признаки печатаются только как «связки» внутри
   пула; нет сводного «признак → все пункты, где встречается» по всему списку.
2. **Мосты между пулами невидимы**: компоненты по построению не пересекаются;
   рёбра ниже порога (слабые мосты П↔П) не отчитываются.
3. **Нет типизации «блокер/гейт»**: похожесть ≠ зависимость. «#31 гейтован
   тестом П5» — направленное отношение, машинный слой его не выражает.
4. **Нет канонной глубины**: пункты сходятся не только лексически, но и в
   графе канона (общие предки по depends_on) — это не вычисляется.
5. **Нумерация #NN позиционная и уже дрейфанула**: OQ_TRIAGE (эпоха 44
   открытых) ссылается на #32/#38/#41 (политика проб), но в текущем
   OQ_POOLS (эпоха 40) #32 = D2 sign-retrieval, #38 = жанр кейсов, #41 нет.
   Любой новый анализ протухнет так же, пока якоря не стабильны.

## 1. Шаги (инкременты, write-through; один шаг переживает обрыв сессии)

### Шаг 0 · Гигиена (механика)

- `python -X utf8 tools/oq_pool.py --write` → свежий машинный слой.

### Шаг 1 · Стабильные якоря пунктов
Дать каждому пункту OPEN_QUESTIONS постоянный якорь, переживающий закрытия.
- Вариант A (рекомендуемый): слаг в конце строки пункта, напр. `{#oq-d10-test}`;
  `oq_pool.py` печатает его рядом с #NN; OQ_TRIAGE переписывается на якоря.
- Вариант B: стабильный ключ = хеш нормализованного текста (файл не правится,
  но ключ нечитаем и ломается при любой правке текста пункта).
- Deliverable: правка `work/OPEN_QUESTIONS.md` + поддержка в `oq_pool.py`
  + ресинхронизированный `OQ_TRIAGE.md`. Без этого шага все следующие отчёты
  дрейфуют так же, как дрейфанул TRIAGE.

### Шаг 2 · Машинный слой пересечений (расширение `oq_pool.py`)
Два новых режима, отчёт → `work/OQ_INTERSECTS.md` (машинная часть):
- `--hubs`: инвертированный индекс «признак → пункты»; ранжирование по
  (вес признака × охват); топ-N хабов, каждый со списком пунктов-свидетельств.
  Стоп-лист против пустых хабов (слишком общие термины типа «тест», «статус»),
  пополняется по факту первого прогона.
- `--cross`: рёбра пункт↔пункт МЕЖДУ разными курируемыми пулами (разметка
  пулов читается из TRIAGE по якорям шага 1); порог мостов ниже основного
  (1–2), каждое ребро помечено «мост П_i↔П_j» + свидетельство.
- Гардрейлы наследуются: χ-склейка запрещена; C-60 вне рёбер; машинный слой
  НЕ типизирует зависимости (это шаг 3, руками) — только similarity.

### Шаг 3 · Слой событий (курируемый — главная новая сущность)
Таблица «**событие E → пункты, которые закрывает/разблокирует**», по одной
строке на событие, со свидетельством (цитатой пункта) на каждую клетку.
Типы событий: формула/оператор · тест-площадка · авторское решение ·
экспорт-пакет · критерий/шаблон закрытия. Отличие от пула: пул = симметричная
похожесть, событие = направленный общий блокер. Deliverable: секция «События»
в `work/OQ_INTERSECTS.md`. Затравка — гипотезы T1–T5 (§2 ниже): проверить,
поправить охват, найти пропущенные.

### Шаг 4 · Канонная глубина (точечно, не грузя корпус)
Для топ-хабов шага 2: где пункты сходятся в самом каноне —
`python tools/query.py deps <ID>` / `context <ID> 1` + graphify-навигация
(дисциплина доверия: EXTRACTED доверяй, INFERRED с оглядкой, AMBIGUOUS —
ручная сверка; при конфликте побеждает канон). Выход: 3–5 «канонных точек
пересечения» — карточек/лемм, являющихся общими предками нескольких пунктов.
Формат: Найдено → зависимости → вывод → что не закрыто.

### Шаг 5 · Синтез и авторское решение
Секция «Точки пересечения» в `work/OQ_TRIAGE.md`: топ-5 точек, каждая =
{узел; какие пункты закрывает/разблокирует (по якорям); цена — сессия /
малое решение / площадка; место в очереди относительно экспорта v14}.
Автор подтверждает или правит порядок работ → строка в DECISIONS.

## 3. Гардрейлы анализа (no-smuggling)

- Каждое ребро/хаб/строка события — со **свидетельством**: [#пункт → признак],
  [карточка ID], [цитата]. Голая похожесть без свидетельства не публикуется.
- Машинная похожесть ≠ зависимость: типизацию «гейт/ждёт/закрывает» ставит
  только курируемый слой (шаг 3), с указанием источника типизации.
- `χ_E ≠ χ-носитель ≠ Q(χ)` — лексическая склейка запрещена (уже в коде).
- Хаб «C-60/политика» закрыт П1 — в рёбра не возвращать.
- Канон не редактируется; статусы карточек не трогаются; verification.py
  (59 PASS) этим анализом не затрагивается вообще.

## 4. Критерии успеха / поражения

- **Успех:** ≥3 точки с рычагом ≥3 пунктов каждая, из них ≥1 конвертируется
  в конкретную сессию-инкремент (уровня «быстрой победы» или одной
  пред-регистрации); T1 переоткрыта (калибровка метода пройдена).

  находится — это отрицательный результат: строка в `work/REFUTED.md`

  новых слоёв не плодить, OQ_INTERSECTS.md не превращать в третий журнал.
