# Энциклопедия ФТС в Obsidian

Хранилище: `E:/projects/Obsidian/FTS`. Начальная страница — `00 — Начало/Начать здесь.md`.

Это производная энциклопедия основного проекта. В ней представлены все действующие карточки канона, узлы и типизированные связи claim_graph. Источники за пределами графа адресуются через карту документов. Энциклопедический текст составителя хранится в `editorial.json`, точность отслеживается по SHA256 исходной записи. Правила для пользователя — [RULES](RULES.md).

## Обновление

Запускать из основного проекта:

```powershell
python -X utf8 tools/obsidian_fts.py --preview
python -X utf8 tools/obsidian_fts.py --write
python -X utf8 tools/obsidian_fts.py --check
```

`--preview` не пишет файлы и показывает число изменений и конфликты. После проверки состава изменений `--write` применяет сборку, повторяя проверку ручных правок. Пользовательское поручение обновить базу разрешает применение, отдельное согласие не требуется. `--check` сверяет исходники, хэши, полноту карточек, адреса всех узлов, точные формулы и внутренние ссылки.

Проверка графа запускается перед экспортом. Устаревший граф не перестраивается молча: сначала исправить или пересобрать его штатной процедурой. Прежний адрес опубликованной сущности сохраняется при изменении названия. Удалённые страницы остаются архивными. Служебный manifest фиксирует все управляемые страницы, источники и соответствия ID. Пользовательская папка и существующие настройки Obsidian не управляются манифестом.

Ручная правка сформированной страницы останавливает всю запись. Копия правки и предлагаемый текст появляются в `90 — Служебное/Конфликты`; исходный файл сохраняется. Для продолжения перенести комментарий в пользовательскую папку либо обновить источник, явно разобрать конфликт и восстановить согласованную страницу. Не менять хэши манифеста, чтобы скрыть конфликт.

## Наполнение и интерфейсы

- Основные страницы: исходный ID, понятное название, псевдонимы, девять разделов описания, таблица свойств и таблица направленных связей, точная исходная запись.
- Обзоры уровней связывают СУ/ЛУ/МУ/операциональное чтение. Когда математическая карточка отсутствует, даётся подписанная строка рабочей карты, если она существует; контекст не приписывается канону.
- Технические оценки статуса и значения адресуются разделами; пользовательские сущности не объединяются по сходству названий. В полном JSON-снимке сохранены все поля узлов и параллельные рёбра.
- `editorial.json`: ключ — ID карточки; `intro_ru`, `caution_ru`, необязательный `example_ru`, `source_sha256`. Хэш считается от `json.dumps(record, ensure_ascii=False, sort_keys=True, indent=2) + '\n'`. Изменение источника отключает прежнее пояснение и выводит обязательство пересмотра.
- Внешние источники открываются локальными file-ссылками с отдельно показанным адресом фрагмента; оригиналы не копируются и не редактируются.

Генератор стандартной библиотеки Python, сетевые сервисы и дополнительные плагины не нужны. Набор проверок:

```powershell
python -X utf8 -m unittest discover -s tools -p test_obsidian_fts.py -v
```

Проверяются покрытие, точность образца уровня 7, внутренние ссылки и три перехода от главной; побайтовая идемпотентность; сохранность заметок и ручных правок; архивирование; устаревание пояснений; стабильность адресов; запрет записи вне хранилища. Временные хранилища тестов создаются только на E:.

## Проверка первой версии — 2026-10-19

Покрытие: 268 карточек канона, 1143 узла и 2751 направленная связь графа. Для 43 ключевых объектов подготовлены отдельные проверенные русские пояснения; остальные статьи сохраняют точное содержание источника и структурное описание. Полнота переноса исходных записей не означает одинаковую степень редакторской проработки.

Для первоначальной версии пройдены восемь интеграционных тестов. В установленном Obsidian 1.14.4 тогда проверены главная страница, таблицы и математическая запись МУ7: формула отрисовывалась MathJax без ошибок. После индексации приложение сообщало 0 неразрешённых внутренних ссылок. Это наблюдение первоначальной версии; расширенный корпус требует отдельной проверки в приложении. Исходные незакрытые обязательства перечислены отдельно и этим числом не отменяются.

Локальные пути источников проверены на существование. Открытие внешнего файла через системную ассоциацию Windows не подтверждено: оно зависит от настроек приложений пользователя. Точный путь и фрагмент источника остаются видимыми в статье.

## Содержательное раскрытие work (в работе)

Помимо точного канона и графа, генератор ведёт независимую перепись всех Markdown-файлов work. Каждый документ получает решение о включении или исключении с причиной; полные включённые тексты доступны внутри базы. Производные экспорты, исторические архивы и полные внешние публикации не объявляются новыми первичными положениями ФТС. Оглавление — «Материалы work», состояние — «Разбор материалов work».

`facets.jsonl` содержит проверенные адресные раскрытия: сущности, тип записи, русский пересказ, область, статус, исходный документ, полный SHA256 и точный диапазон строк с дословной цитатой. `document_reviews.json` отдельно фиксирует полное содержательное чтение документа; наличие текста в базе или буквального ID не считается таким чтением. Источник изменился — прежнее раскрытие отключается и помечается требующим пересмотра; исходная запись сохраняется в служебном снимке. Ошибка точности цитаты при неизменном хеше останавливает сборку.

В статьи также включаются вопросы из всех 536 карточек слоя claim_questions с их фактическим answer_status, corpus_coverage, происхождением и авторской проверкой. Наличие источника ответа не считается полученным ответом. Содержательная полнота не установлена, пока остаются неразобранные документы и сущности без адресного раскрытия; очередной успешный файловый тест не закрывает это обязательство.

Расширение: 744 раскрытия для 268 карточек; полностью прочитаны 106 из 221 включённого Markdown-документа и 12 материалов иных форматов (два артефакта OC01…OC15 и десять таблиц реестра). В переписи всех иных форматов — 256 файлов с решениями об исключении либо состоянием разбора. Хэш подтверждает актуальность отметки чтения; он не доказывает исчерпывающего извлечения свойств. Пройдены 19 интеграционных тестов. Точный остаток требований — [DISCLOSURE_AUDIT.md](DISCLOSURE_AUDIT.md).


## Исследовательский реестр v1.2

Все 127 CP-предложений имеют основной адрес: 94 ведут к существующим каноническим карточкам, 33 — к самостоятельным исследовательским страницам. Файлы последних адресованы стабильным ID; русские названия и прежние обозначения доступны как псевдонимы. Реестр доступен прямо с главной страницы. Пояснения 33 предложений хранятся отдельно в `registry_editorial.json`; для каждого сохранены SHA256 первичной таблицы и таблицы решений. Изменение любого основания отключает прежний пересказ, область и редакторский пример до пересмотра, сохраняя точные текущие записи.

Точные строки G1…G9, решение от 2026-10-18, происхождение, тип, уровни, ограничения и ссылки на вопросы показаны раздельно. Открытый выбор, противоречие и заменённая формулировка не сводятся к одному статусу. Исходный `status` реестра не заменяет отдельные оси авторского принятия, St_FTS, математической проверки и эмпирической поддержки. Ссылки на карточки из поля `cards` служат адресными связями исследования, без наследования свойств. Полный разбор всех первичных документов, на которые ссылается реестр, остаётся частью продолжающейся задачи.

Исправлено соединение строк сформированных таблиц свойств и статусов: между строками таблицы нет пустых абзацев. Дословные цитаты и исходные документы не преобразуются этой правкой.
