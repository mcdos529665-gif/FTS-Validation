# PREREGISTRATION — D2 / «Половина_А» как кодирование знаковой неопределённости

Коммитится ДО прогона (как o20). Гипотеза, дизайн, метрика, первичный контраст и
правило решения зафиксированы заранее. Прогон — `run_d2.py` (детерминирован, seed ниже).

## Что тестируем

D2 (главный риск half_hypothesis §5): даёт ли «Половина_А» — чтение У8, где величина
известна, а **знак/ветвь открыты и разрешаются через порождающее отношение** (У9: `x³=x·x²`)
— роль СВЕРХ плоского `¬A` («знак неизвестен», флаг). Если не даёт — это переименование
(провал F3 / QuestionGain O_14), статус остаётся `candidate/analogy_only`.

Операционализация: признак, у которого **потерян знак** (наблюдаем `|x|`), в задаче,
где знак предиктивен. Три кодировки потери знака — параллельно o20 (T1/T2/T3):

- **T1 (забыть):** `|x|` вместо знакового значения. Знак выброшен, флага нет.
- **T2 (плоский ¬A):** `|x|` + бинарный флаг «знак потерян» (по признаку/строке).
- **T3 («Половина_А»):** T2 + **разрешение через порождающее отношение** —
  взаимодействия `|x| · контекст` (аналог `x³=x·x²`: знак восстанавливается произведением
  с порождающей структурой; линейная модель так может реконструировать `знак·|x|`).
- **ORACLE:** истинное знаковое `x` (верхняя граница; не кодировка, а потолок).

## Честная оговорка (пред-зарегистрирована)

Когда знак потерян, `|x|` + контекст — **вся** доступная информация. T3 добавляет не
сырую информацию, а СТРУКТУРУ разрешения (взаимодействия). Поэтому:
- **гибкая модель** (HistGB) учит взаимодействия сама → ожидаем `T3≈T2` (null). Такой
  null НЕ опровергает ФТС внутренне — он показывает отсутствие внешней **кодировочной**
  роли (ровно скромный статус, который гипотеза и держит сейчас).
- **линейная модель** (LogReg) сама произведения не строит → у T3 есть реальный шанс.
  `T3>T2` тут = «структура-разрешение помогает ограниченным моделям» (слабая/частная роль).

То есть это тест именно кодировочной роли, не всей формальной теории формы.

## Дизайн

- Панель (binary classification, числовые признаки), `fetch_openml` + sklearn builtin:
  `breast_cancer` (builtin, гарантирован), `ionosphere`, `sonar`, `diabetes`. Неудачный
  fetch — пропустить (записать).
- Признаки z-стандартизируются (становятся знаковыми). «Неоднозначные» = половина
  признаков (детерминированно по индексу). Для них у доли `p=0.5` строк знак теряется
  (детерминированная маска по seed): храним `|z|` + флаг. Остальные признаки — чистые
  (контекст).
- Модели: `LogisticRegression` (линейная) и `HistGradientBoostingClassifier` (гибкая).
- Оценка: `RepeatedStratifiedKFold` (5 splits × 4 repeats), метрика **ROC-AUC**, по фолду
  для каждой кодировки. Внутри фолда — стандартный пайплайн (масштабирование для LogReg).
- SEED = 20260615 (везде).

## Первичный контраст и правило решения (заранее)

- **Первичный:** `T3 − T2` AUC для **HistGB** (гибкая), пул по датасетам×фолдам,
  односторонний Wilcoxon (`T3>T2`), α=0.05.
- **Вторичный:** то же для **LogReg** (линейная — лучший шанс T3).
- **Опорные (платформа):** `ORACLE − T2` (есть ли «комната»: знак вообще предиктивен);
  `T2 − T1` (помогает ли флаг — санити, как слабая площадка o20).

Вердикт (фиксируется до прогона):
- **CONFIRMED:** `T3>T2` значимо для HistGB → внешняя кодировочная роль есть (сильно).
- **WEAK:** `T3>T2` только для LogReg → Половина_А = инженерный приём для слабых моделей,
  не глубокая роль.
- **NOT CONFIRMED:** `T3≈T2` (обе) → внешней кодировочной роли НЕТ; «Половина_А» остаётся
  `candidate/analogy_only`; центральная гипотеза НЕ повышается через D2-кодировочный путь.
- Если `ORACLE≈T2` (знак не предиктивен на панели) → площадка слабая, тест неинформативен
  (зафиксировать как o20-подобную оговорку, не выдавать за чистый результат).

## Что меняется по итогу

- CONFIRMED/WEAK → апдейт half_hypothesis §5 (D2 частично пройден) + рассмотреть фолд в
  статью (решение A+C).
- NOT CONFIRMED → D2-кодировочный путь закрыт отрицательно; статус не меняется; запись —
  честный отрицательный результат (как o20). Решающим для ФТС остаётся внутренняя роль
  (которую этот тест не покрывает).
