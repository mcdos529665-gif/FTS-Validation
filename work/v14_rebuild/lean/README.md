# Lean: формальные доказательства математического ядра ФТС

Пакет добавляет проверяемые ядром Lean доказательства пяти существующих
математических предикатов и входит в обязательный маршрут как `lean_proofs`.

| Проверка | Теорема | Точная область |
|---|---|---|
| C01 | `FTS.antiform_eq_iff_zero` | Для всякого a∈ℝ: a=−a ↔ a=0 |
| C03 | `FTS.abs_reflection` | Для всякого x∈ℝ: |−x|=|x| |
| C04 | `FTS.abs_fiber` | Для любых a,b∈ℝ: |a|=|b| ↔ a=b или a=−b |
| C09 | `FTS.square_branch_collision` | Над ℝ: 1²=(−1)² при 1≠−1 |
| C49 | `FTS.square_idempotents` | Для всякого x∈ℝ: x²=x ↔ x=0 или x=1 |

Исходные утверждения — соответствующие функции `verification.py`; привязка и
машинные типы — [proofs.tsv](proofs.tsv). C01 доказан для любого значения и применим
поточечно к функциям исходной проверки. Это математическое ядро; семантика уровней
и `St_FTS` из него не следуют. Новые математические утверждения и предикаты
C-проверок не вводятся, отдельная повторная CAS-проверка неизменённых фактов не нужна.

## Запуск из корня проекта

```text
python -X utf8 tools/lean.py setup
python -X utf8 tools/lean.py check
python -X utf8 tools/check_project_consistency.py
```

`setup` — однократная установка. Проверка `check` не устанавливает и не обновляет
окружение. Для полного Python-набора нужен SymPy; на текущем компьютере он доступен
через `py -3.11`. По умолчанию `check` выводит итог без перезаписи отчёта.
Явное сохранение результата: `tools/lean.py check --report <путь.json>`.
Код 0 — PASS, 1 — ошибка сборки/проверки/окружения, 2 — параллельный запуск держит
блокировку. Ошибка окружения не является математическим опровержением.

## Окружение

Закреплены Lean `v4.35.0`, Mathlib `56a005855ea17e0b0958f73ec801ae140b0a1679`
(релиз `v4.35.0`) и транзитивные зависимости в `lake-manifest.json`.
Обновление версий требует отдельного изменения и повторной проверки.

На Windows установка, Mathlib, кеши и рабочая копия Lake находятся под
`E:/Codex/tools/lean/`. Исходники зеркалируются туда при запуске;
`.lake` в репозитории не создаётся. Пользовательские PATH и настройки редактора
не меняются. Другой путь задаётся `FTS_LEAN_HOME` или `--home` и должен совпадать
при установке и проверке. После аварийного завершения файл блокировки с PID
удалять только убедившись, что этот процесс завершён.

На Linux/macOS сначала установить elan в `$FTS_LEAN_HOME/elan` по официальной
инструкции, затем выполнить `setup`. Автоматическая установка рассчитана на Windows.
Текущая среда проверена на Windows; при медленной загрузке через elan официальный
архив Lean можно установить вручную в его каталог toolchains после сверки SHA256
с данными официального релиза, затем продолжить `setup`.

## Что проверяется

1. Закреплённые версии и чистота исходников зависимостей.
2. Сборка FTS и повторная обработка локальных модулей доказательств.
3. Соответствие типов теорем машинным утверждениям из `proofs.tsv`.
4. Аксиомы каждого зарегистрированного доказательства через `#print axioms`.

Разрешены стандартные основания Lean/Mathlib: `propext`, `Classical.choice`,
`Quot.sound`. Пользовательская аксиома, `sorryAx` или вычислительный обход
`Lean.ofReduceBool` приводит к ошибке. `sorry` также запрещён режимом предупреждений
как ошибок. Готовые модули Mathlib входят в доверенную закреплённую зависимость;
это не независимая пересборка всей библиотеки другим проверяющим ядром.

[Сохранённый результат](verification_result.json) содержит SHA256 исходников,
реестра, конфигурации и манифеста. Это результат конкретного снимка;
актуальность подтверждается живой проверкой.
При изменении исходников или Python-проверок обновить результат явно:
`python -X utf8 tools/lean.py check --report work/v14_rebuild/lean/verification_result.json`,
затем пересобрать граф и исследовательскую выгрузку штатными командами.
Обычный `check` отвергает устаревший сохранённый снимок.

Проверено 2026-10-18: пять доказательств PASS. В живых отрицательных проверках
отвергнуты ложное равенство `1 = 0`, заглушка `sorry` и теорема, основанная на
пользовательской аксиоме. Три теста разбора аудита также прошли. Свидетельство
зарегистрировано в графе: `LEAN_C01/C03/C04/C09/C49` → `lean_kernel_20261018`.

Новый факт: доказательство в `FTS/`, импорт в `FTS.lean` при необходимости,
строка с точной областью и типом в `proofs.tsv`, затем `check`.
Правильность перевода неформального тезиса в формальный тип проверяет человек.

[Lake](https://lean-lang.org/doc/reference/latest/Build-Tools-and-Distribution/Lake/),
[кеш Mathlib](https://github.com/leanprover-community/mathlib4/blob/master/Cache/README.md).
