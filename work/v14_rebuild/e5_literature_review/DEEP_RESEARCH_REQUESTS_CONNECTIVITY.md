# Запросы ChatGPT Deep Research для внешней проверки оснований связности ФТС

- Дата пакета: 2026-09-09
- Статус: `research_request_plan`
- Объект проверки: основания связности `[O_01]…[O_20]`
- Режим: внешнее исследование; результаты не входят в канон автоматически
- Связанный OQ: `oq-systematic-literature-review`

## Найдено → зависимости → вывод → что не закрыто

**Найдено.** Основания связности требуют разных видов внешней проверки. Для
`O_01…O_12` нужно искать формальные аналоги, пределы применимости и независимые
альтернативы канонной цепочке. Для кандидатных `O_13…O_20` нужны источники,
которые позволяют поставить абляцию, измерение или явный контрпример.

**Зависимости.** Точные формулировки и статусы берутся только из карточек
`O_01…O_20`; критерии поражения — из `[O_12]` и `[F1]…[F5]`. Результаты
маршрутизируются через `PROTOCOL.md`, `EVIDENCE_MATRIX.tsv`, `REFUTED.md` и
`work/EXTERNAL_CONFLICTS.md`. Регистр, область и тип связи нельзя достраивать
по совпадению терминов.

**Вывод.** Ниже подготовлены общий префикс и 24 самостоятельных задания для
ChatGPT Deep Research: одно по исходной статье, двадцать по основаниям и три
поперечных стресс-теста. Каждый запрос ищет подтверждающие, ограничивающие,
альтернативные и опровергающие результаты симметрично.

**Что не закрыто.** Этот файл является программой поиска, а не результатом
обзора. Не выполнены discovery, citation-network coverage, второй независимый
screening и adjudication. Ни одна формулировка ниже не меняет `St_FTS`.

## 1. Как запускать запросы

Для каждого задания создать отдельный сеанс ChatGPT в режиме **Deep Research**.
Приложить `FTS_research_project_for_AI.md` либо минимальный пакет из карточки
основания, `PROJECT_INSTRUCTIONS.md`, `work/notation.md` и
`work/EXTERNAL_CONFLICTS.md`. Не объединять все задания в один поиск: тематические
области и критерии качества у них различаются.

В начало каждого задания вставлять общий префикс из §2, затем тело одного
запроса из §4–§7. Полный текст ФТС передавать только в ChatGPT; сторонним
поисковым сервисам достаточно поисковых строк и библиографических метаданных.

Рекомендуемый порядок:

1. `DR-00` — разобрать исходную статью и построить от неё citation graph.
2. `DR-07`, `DR-08`, `DR-09`, `DR-14` — проверить ближайшие формальные связи.
3. `DR-X1`, `DR-X2` — искать вставку, схлопывание и независимую альтернативу.
4. Остальные запросы — по одному основанию, начиная с хабов открытых вопросов.
5. `DR-X3` — отдельно от формального контура проверить культурные гипотезы.

## 2. Общий префикс для каждого запроса

```text
Проведи глубокое академическое исследование конкретного основания связности ФТС,
приведённого ниже. ФТС — локальный объект исследования; не подставляй обычное
значение перегруженных терминов. Канон ФТС сохраняется как объект описания, но
любой производный claim может быть ограничен или опровергнут.

Ищи четыре класса внешнего материала симметрично:
1) direct — тот же предикат в сопоставимой области;
2) limiting — результат, задающий необходимые условия или более узкую область;
3) alternative — независимый формализм, покрывающий ту же функцию;
4) refuting — теорема, контрпример или надёжный эмпирический результат против claim.
Совпадение слов без отображения объектов, операций, области и кванторов помечай
analogy и не используй как подтверждение.

Приоритет: первичные рецензируемые статьи, монографии и официальные формальные
библиотеки. Для каждого источника проверь существование, авторов, год, точный
заголовок, DOI/arXiv/издательскую запись и наличие исправлений или ретракций.
Обзоры используй для навигации, а решающий вывод сверяй с первоисточником.
Проведи backward/forward citation search минимум для двух сильнейших работ.

Для каждого найденного результата выпиши:
- точный внешний предикат или эмпирический эффект;
- объекты, операции, область, кванторы и предпосылки;
- страницу, раздел, номер определения/теоремы/таблицы;
- отображение на элементы ФТС и место, где отображение перестаёт работать;
- relation = direct|limiting|alternative|refuting|analogy;
- strongest counterevidence и альтернативное объяснение;
- verdict = supports_local_instance|limits|nonconfirmation|contradicts_same_domain|
  independent_alternative|insufficient_evidence.

Не заявляй мировую новизну по отсутствию результатов. Не повышай статус ФТС.
Если обнаружено расхождение, подготовь запись для EXTERNAL_CONFLICTS: обе стороны,
точные источники, область/регистр, мост, свидетель, решение и незакрытый остаток.

Финальный ответ представь как: Найдено → зависимости → вывод → что не закрыто,
затем evidence matrix, список включённых/исключённых источников, поисковые строки,
базы, даты поиска и краткий citation-graph log.
```

## 3. Обязательная таблица результата

Каждый отчёт должен закончиться таблицей:

| Поле | Требование |
|---|---|
| FTS claim | дословная карточка и статус |
| External claim | точная формулировка без пересказа сильнее источника |
| Domain match | `same / partial / different` с объяснением |
| Mapping | объекты, операции, кванторы и цена |
| Relation | `direct / limiting / alternative / refuting / analogy` |
| Evidence quality | тип исследования, рецензирование, воспроизводимость |
| Defeat test | что уничтожает локальный вывод |
| Conflict action | `none / EC-new / EC-revision / REFUTED` |
| Status effect | всегда «нет автоматического изменения» |

## 4. Начальный источник и ближайший формальный кластер

### DR-00 · Ranzato–Tapparo как исходный узел citation graph

**Исходник:** Francesco Ranzato, Francesco Tapparo, *Generalized Strong
Preservation by Abstract Interpretation*, arXiv:`cs/0401016v3` (2006),
<https://arxiv.org/abs/cs/0401016v3>. Локальный неизменяемый пакет:
`arxiv/cs_0401016v3/`.

```text
Разбери статью Ranzato и Tapparo Generalized Strong Preservation by Abstract
Interpretation, arXiv:cs/0401016v3, как возможный внешний мост к O_07, O_08,
O_09 и O_14 ФТС. По полному тексту установи точные определения strong
preservation, completeness, partitioning abstract domain, refinement и complete
shell; найди номера результатов о существовании минимального уточнения и
greatest fixed point. Отдельно ответь:

1. В каком порядке находятся абстрактные домены и что именно означает minimal?
2. Является ли найденное уточнение уникальным, и при каких предпосылках?
3. Следует ли из результата наличие cover relation или локальная
   невставляемость, либо между доменами могут существовать промежуточные объекты?
4. Как strong preservation зависит от выбранного языка L?
5. Какие независимые алгоритмы partition refinement и поведенческие
   эквивалентности получаются как частные случаи?

Построй backward citation set основных предшественников и forward citation set
до текущей даты. Найди последующие работы, которые усиливают, ограничивают или
опровергают применимость результата. Сопоставление с ФТС разрешено только после
явной типизации: конкретные состояния, язык вопросов, порядок уточнений,
проекции и цена. Не выводи из статьи порядок уровней ФТС.
```

Предварительная роль источника: `direct component / limiting / alternative` для
уточнения различимости; не подтверждение лестницы целиком. Аннотация arXiv прямо
говорит о склейке неразличимых состояний, strong preservation и минимальном
уточнении как greatest fixed point; теоремный уровень должен проверить Deep
Research по полному тексту.

### DR-07 · `[O_07]` Локальная невставляемость

**Claim:** `Dense_FTS(−1..7 | Σ_FTS,C,T)`; вставка `X` должна быть исключена в
заданном классе представлений.

```text
Найди формальные теории refinement order, partition lattice, abstract
interpretation, expressive hierarchy и minimal basis, в которых соседство двух
представлений можно доказать как cover relation: промежуточный объект либо
эквивалентен краю, либо нарушает заданные ограничения. Ищи также отрицательные
результаты: плотные решётки уточнений, интерполяционные теоремы и явные
промежуточные представления. Проверь, даёт ли Ranzato–Tapparo cover relation или
только наименьшее полное уточнение относительно языка L. Требуемый итог — условия,
при которых O_07 получает локальный внешний инстанс, и сильнейший кандидат X,
который может выполнить F1.
```

Поисковые семьи: `cover relation partition refinement lattice`, `minimal
strongly preserving abstract domain`, `intermediate abstraction completeness`,
`expressiveness hierarchy interpolation counterexample`.

### DR-08 · `[O_08]` Двухшаговая проекция

**Claim:** `π_{n+2→n}(M_{n+2})=M_n*`; `Expand₂/Compress₂` связывают малую и
расширенную формы.

```text
Найди теоремы о проективных/обратных системах, Galois insertion/connections,
abstract interpretation refinement, quotient/section и multiresolution models,
где более богатое представление допускает проверяемую проекцию на прежний слой.
Отдели существование произвольной проекции от сохранения конкретного вопроса,
операции или семантики. Ищи контрпримеры, где локальные проекции существуют, но
не согласуются по композиции, или где расширение не сохраняет нижний слой.
Сформулируй минимальную commuting-diagram спецификацию локального инстанса O_08
и проверь, следует ли она из strong preservation/completeness.
```

### DR-09 · `[O_09]` Независимая альтернатива `M′`

**Claim:** независимая модель должна покрыть функции, стоимость и связность без
скрытой ФТС.

```text
Найди независимые формализмы для иерархий различимости: abstract interpretation,
Blackwell order of experiments, bisimulation/behavioural equivalence, formal
concept analysis, sufficient statistics, information lattice и state abstraction.
Для каждого построй таблицу покрытия функций, вычислительной/описательной цены
и связности. Запрещено переименовывать уровни ФТС. Определи, может ли один
формализм дать M′ с не большей ценой и тем же проверяемым поведением, и какой
эксперимент различит M′ и ФТС. Особо проверь модели, выводимые из
Ranzato–Tapparo без предположений ФТС.
```

### DR-14 · `[O_14]` QuestionGain

**Claim:** вопрос следующего уровня невыразим ниже без скрытого аппарата при
сопоставимой цене.

```text
Найди эквивалентные или близкие критерии нового вопроса в Blackwell sufficiency,

abstract interpretation completeness/strong preservation и representation

случаи синергии, когда два бесполезных по отдельности вопроса полезны совместно.

несовпадение, если одно минимально по представлению, а другое — по языку/домену.
```

## 5. Запросы по канонным основаниям `[O_01]…[O_12]`

### DR-01 · `[O_01]` Среда уровня

```text
Проверь внешний claim: более высокий режим различимости операционально требует
среды предыдущего режима. Ищи формальные определения context dependence,
hierarchical state machines, layered semantics, compositional type systems и
hierarchical representations. Требуй явный закон зависимости, а не рисунок
слоёв. Ищи контрпримеры: независимые ветви, skip connections, emergent variables
и новые observables, определимые без нижнего носителя. Итогом должна быть
минимальная формула Environment(U_{n+1},U_n) и условия её поражения.
```

### DR-02 · `[O_02]` Тотализация уровня

```text
Исследуй, существуют ли формальные результаты, где замыкание или тотализация
языка/абстракции уничтожает возможность следующего различения, пока не добавлен
новый observable. Ищи в abstract interpretation completeness, closure operators,
diagonal arguments, non-definability, logical expressiveness и sufficient
statistics. Отдели «модель полна относительно языка» от «новый уровень
невозможен». Найди контрпример, где тотальная нижняя теория допускает строгое
консервативное расширение. Определи, какой внешний предикат действительно
соответствует `Tot(U_n) → ¬U_{n+1}` и не смешивает `¬A` с `0_A`.
```

### DR-03 · `[O_03]` Реверси

```text
Ищи формальные конструкции, где объект A вместе с типизированной информацией о
его отсутствии 0_A порождает новый тип вопроса или представления. Области поиска:
partiality/option types, pointed types, modal and paraconsistent logics,
belief revision, provenance and missingness mechanisms. Отдельно найди случаи,
где добавление bottom/null ничего не увеличивает или сводится к булеву флагу.
Проверь необходимость каждого компонента A/0_A и запрети замену структурированного
отсутствия обычным отрицанием. Итог — либо типизированный локальный конструктор,
либо свидетель отсутствия известного прямого аналога.
```

## 8. Правило принятия результата в проект

1. Отчёт без воспроизводимого поискового журнала возвращается на доработку.
2. Источник без проверяемой записи помечается `unverified` и не попадает в
   evidence matrix как основание.
3. `analogy` не становится `direct` из-за числа похожих терминов.
4. Подтверждение компонента не подтверждает порядок всей лестницы.
5. Неподтверждение не объявляется опровержением без сопоставимой области.
6. Прямое противоречие в одной области записывается в `EXTERNAL_CONFLICTS.md`;
   ошибка рабочего claim дополнительно — в `REFUTED.md`.
7. Любое изменение `St_FTS` требует отдельного SP-решения и критериев К1–К5;
   Deep Research сам статусы не меняет.
8. Для arXiv-источника, принятого в корпус, сохраняются фиксированная версия,
   исходники, официальный PDF, производный Markdown и SHA-256 по правилам проекта.
