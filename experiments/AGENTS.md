# Эксперименты OpenResearch (`orx`) в проекте ФТС

Этот файл — контракт для агентов, которых запускает OpenResearch (Claude Code,
Codex и др.) в этом репозитории. Он дополняет корневые `AGENTS.md` / `CLAUDE.md`
и при конфликте с инструкциями OpenResearch (playbook, модули `orx skill`)
имеет приоритет. Корневые правила проекта действуют полностью.

## Граница записи

- Эксперимент OpenResearch — ветка `orx/<slug>`. В такой ветке разрешено менять
  **только** `experiments/<slug>/` своего эксперимента (и `experiments/ACTIVE`,
  см. ниже). Всё остальное — `source/`, `work/`, `tools/`, `arxiv/`,
  `graphify-out/`, корневые файлы, чужие `experiments/<другой>/` — только чтение.
- Граница проверяется: git-хук `tools/hooks/pre-commit` отклоняет коммит в ветке
  `orx/*` с путями вне `experiments/`; `experiments/run.py` повторяет проверку
  перед запуском. `--no-verify` и обход хука запрещены.
- В `master` не коммитить, ветки `orx/*` в `master` не сливать, ничего не пушить.
  Перенос результата в теорию (`work/`, `source/`, статья) делает основная сессия
  по решению автора, а не агент эксперимента.

## Статус результата

- Всё в `experiments/` — рабочий слой `candidate`/`overlay`, не
  `canonical_strict`. Эксперимент не повышает статусы, не меняет `St_FTS`,
  не пишет «принято автором». Повышение — только через `SP_*` и К1–К5
  (`PROJECT_INSTRUCTIONS.md#status`).
- No-smuggling: термины ФТС брать из артефактов; выводы помечать
  `[карточка ID]` / `[триплет s→p→o]` / `[лист row]` / `[внешнее]`;
  чего нет — «нет в артефактах». Литература из `orx discover` / `orx paper` —
  всегда `[внешнее]`; конфликт с каноном записывается в отчёт эксперимента
  (в `work/EXTERNAL_CONFLICTS.md` его переносит основная сессия).
- FAIL ≠ контрпример: сначала диагностика причины.

## Устройство эксперимента

```
experiments/
  ACTIVE              имя каталога эксперимента, который запускает run.py
  run.py              общий фиксированный запуск (команда проекта в orx)
  <slug>/
    README.md         гипотеза, что меняется, что измеряется, условие поражения
    run.py            точка входа эксперимента
    results/          выводы прогонов, таблицы, графики
    REPORT.md         Найдено → зависимости → вывод → что не закрыто
```

- Команда проекта в orx фиксирована: `py -3.11 -X utf8 experiments/run.py`.
  Её не менять (правило orx №2). Эксперимент выбирается коммитом в
  `experiments/ACTIVE`, а не переменными окружения.
- `<slug>` совпадает с суффиксом ветки `orx/<slug>`.
- Отчёты и артефакты — в `experiments/<slug>/`. Если playbook OpenResearch
  требует каталог артефактов, туда кладётся копия; источник истины —
  `experiments/<slug>/`.
- Python: `py -3.11 -X utf8`; запись текстов — с `newline="\n"`.
- Корневые проверки (`tools/verify.py --strict`,
  `work/v14_rebuild/verification.py`) запускать можно — они только читают.

## Отчёт

`REPORT.md` и итог сессии: **Найдено → зависимости → вывод → что не закрыто**.
Отдельно перечислить, что из вывода опирается на канон, а что `[внешнее]` или
является предложением ассистента.
